# CLAUDE.md — MarkdownEditor

## O que é

Aplicação **WinUI 3** (Windows App SDK 2.x, `net10.0-windows10.0.26100.0`, mínimo Windows 10 1809) para visualizar e editar arquivos `.md`, `.markdown`, `.json`, `.xml` e `.txt`, com visual Fluent Design nativo.

Solução: `MarkdownEditor.slnx` com um único projeto, `MarkdownEditor/MarkdownEditor.csproj`.

## Projeto

- `UseWinUI`, **sem pacote MSIX** (`WindowsPackageType=None`) e **Windows App SDK self-contained** (`WindowsAppSDKSelfContained`) e `EnableMsixTooling=true` (sem ele o `dotnet publish` não leva o `MarkdownEditor.pri`, que contém o XAML compilado, e o exe instalado fecha ao abrir com `0xC000027B`); o .NET continua framework-dependent. Distribuição pelo instalador Inno Setup.
- `RuntimeIdentifier` padrão `win-x64` (ou `win-arm64` com `Platform=ARM64`), exigido pelo self-contained.
- Pacotes: `Microsoft.WindowsAppSDK`, `Microsoft.Windows.SDK.BuildTools`, `CommunityToolkit.WinUI.Controls.Segmented` (Visualizar/Editar) e `CommunityToolkit.WinUI.Controls.Sizers` (`GridSplitter`). O WebView2 vem com o Windows App SDK.
- `app.manifest`: DPI PerMonitorV2. `Markdown.ico` (raiz) é copiado como `Assets\Markdown.ico` (ícone da janela e da `TitleBar`).
- `wwwroot\**` copiado para a saída (`Content`, `PreserveNewest`).

## Arquitetura

- **`App.xaml.cs`**: `OnLaunched` pega o primeiro argumento de `Environment.GetCommandLineArgs()` que seja um arquivo existente e passa para `new JanelaPrincipal(arquivoInicial)`. É assim que funciona o duplo clique no Windows (o Windows passa o caminho como `%1`). O programa **não** grava associação de arquivos no Registro — isso foi decidido explicitamente. Quem registra é o **instalador** (ver "Geração do Instalador"); sem o instalador, a associação é feita manualmente pelo usuário via "Abrir com".
- **Exceções**: `Application.UnhandledException` (marca `Handled`, `Trace` e mostra `ContentDialog` por `JanelaPrincipal.MostrarErroInesperado`) e `AppDomain.UnhandledException` (só `Trace`). `async void` apenas em event handlers; métodos assíncronos disparados de outros pontos são `async Task` e chamados por `Disparar(tarefa)`, cuja exceção chega ao `UnhandledException`.
- **Arquivos da `JanelaPrincipal`** (classe `partial`): `JanelaPrincipal.xaml` / `.xaml.cs` (constantes, campos, construtor, `Loaded`, fechamento), `JanelaPrincipal.Arvore.cs`, `.Preview.cs`, `.Editor.cs`, `.Monitor.cs`, `.Historico.cs`, `.Tema.cs`, `.Dialogos.cs` e `.Sobre.cs`; agrupados sob o XAML no `.csproj` (`DependentUpon`). P/Invoke em `NativeMethods.cs` (`LibraryImport`; só `SHGetFileInfo` continua com `DllImport`, porque a struct usa `ByValTStr`; `AllowUnsafeBlocks` no `.csproj`), usado apenas pelos ícones da árvore.
- **Layout Fluent** (`JanelaPrincipal.xaml`):
  - `MicaBackdrop`, `ExtendsContentIntoTitleBar` + controle `TitleBar tlbTitulo` (ícone, título com `*` quando há alterações, botão de painel `IsPaneToggleButtonVisible` → `AlternarArvore`).
  - `CommandBar cbrComandos`: `abbVoltar`/`abbAvancar`, `Segmented sgmModo` (Visualizar/Editar, dentro de `AppBarElementContainer`), `absSalvar` + `abbSalvar`/`abbDesfazer` (só no modo Editar) e `abbSobre`. Atalhos por `KeyboardAccelerator` nos botões (Alt+←/→, `GoBack`/`GoForward`, Ctrl+S, F1); acelerador de botão desabilitado ou oculto não dispara.
  - Corpo `grdCorpo`: coluna `colArvore` (`MinWidth` = `LarguraMinimaArvore`, 50) com `TreeView trvPastas`, `GridSplitter gspDivisoria` e o "card" `grdConteudo` (borda e cantos de tema) com `WebView2 wvwPreview` e `WebView2 wvwEditor` (só um visível).
  - Cores só por `ThemeResource`; tamanho inicial e mínimo da janela em `AjustarTamanhoJanela` (pixels lógicos × `RasterizationScale`, `OverlappedPresenter.PreferredMinimum*`).
- **Diálogos** (`JanelaPrincipal.Dialogos.cs`): `ContentDialog` no `XamlRoot` da janela, com `SemaphoreSlim` (o WinUI só permite um aberto por vez): `AvisarAsync` (OK), `PerguntarSimNaoAsync`, `PerguntarSalvarAsync` (Salvar/Não salvar/Cancelar → `RespostaSalvar`). Tema do diálogo = `grdRaiz.RequestedTheme`.
- **Sobre** (`JanelaPrincipal.Sobre.cs`): `abbSobre` (F1) abre um `ContentDialog` (mesma fila `_filaDialogos`) com ícone, produto, a frase `DescricaoSobre`, versão (`AssemblyInformationalVersion` sem o sufixo `+hash`), arquitetura, .NET, Windows App SDK (constantes `Microsoft.WindowsAppSDK.Release`, geradas pelo pacote com `WindowsAppSdkIncludeVersionInfo` no `.csproj`; o `ReleaseInfo.AsString` do WinRT falhava no app self-contained), WebView2 Runtime, Monaco (constante `VersaoMonaco`), Windows, a pasta de instalação (`AppContext.BaseDirectory`), "Fontes" (`HyperlinkButton` para `UrlFontes`, o repositório no GitHub) e o copyright. "Copiar informações" copia o texto sem fechar o diálogo (não usa `AvisarAsync`, que travaria com a fila ocupada).
- **Árvore** (`JanelaPrincipal.Arvore.cs`):
  - Raízes: Área de Trabalho, Documentos, Downloads e `DriveInfo.GetDrives()` (somente `IsReady`).
  - Modo de nós: `TreeViewNode.Content` é um `ItemArvore` (`Nome`, `Caminho`, `EhArquivo`, `Chave`, `Icone` com `INotifyPropertyChanged`); o `ItemTemplate` usa `x:Bind` com cast (`((local:ItemArvore)Content).Icone`, `OneWay`).
  - Carregamento lazy: pasta nasce com `HasUnrealizedChildren = true`; `CarregarFilhos` (chamado no `Expanding` e pelo `SelecionarNaArvore`) lê subpastas + arquivos filtrados por `ExtensoesSuportadas`. Pastas ocultas/sistema são ignoradas; `UnauthorizedAccessException`/`IOException` resultam em nó vazio.
  - Ícones (`IconesShell`): `SHGetFileInfo` (mesmo ícone do Explorer) desenhado com `DrawIconEx` numa seção DIB de 32 bits no tamanho físico (16 px × `IconesShell.Escala`, definida no `Loaded` pela `RasterizationScale`) e copiado para um `WriteableBitmap`. Síncrono, com cache por chave: caminho para pastas especiais e unidades (`DoCaminho`), `"pasta"` e `"ext.<extensão>"` com `SHGFI_USEFILEATTRIBUTES`, sem acessar o disco (`DoTipo`). O ícone é definido ao criar o nó. A primeira tentativa com `GetThumbnailAsync` (WinRT) não exibiu nenhum ícone — não voltar a ela.
  - Seleção: toda seleção feita pelo programa passa por `SelecionarNo` (`_ignorarSelecao` + `_noSelecionado`); `trvPastas_SelectionChanged` só trata as do usuário. Como não há "BeforeSelect", com alterações pendentes a seleção volta ao nó anterior, `ConfirmarDescarteAsync` e, se confirmado, seleciona e exibe. `SelecionarNaArvore(caminho)` **só seleciona** (expande até o item e chama `TrazerParaVisao`, que, por causa da virtualização, primeiro pede `ScrollIntoView(no)` ao `ListView` interno do `TreeView` — achado com `DescendenteDoTipo` — e só então usa `ContainerFromNode(no).StartBringIntoView()`; só o `StartBringIntoView` não funcionava para nós fora da área já renderizada); quem quer exibir chama `ExibirArquivoAsync`.
  - Menu de contexto `mfoArvore` (criado em código em `ConfigurarMenuArvore`), aberto em `trvPastas_ContextRequested` para o nó sob o clique (`TreeViewItem` ancestral do `OriginalSource` → `NodeFromContainer`) ou o selecionado (teclado), sem alterar a seleção: "Abrir local do arquivo"/"Abrir pasta" (`explorer.exe /select,` ou `AbrirComShellAsync`), "Copiar caminho completo" e "Copiar nome do arquivo"/"Copiar nome da pasta" (raiz de unidade copia o caminho; `DataPackage` + `Clipboard.Flush`). Textos de `TextosMenu`; ações (`AbrirLocalAsync`, `CopiarCaminhoAsync`, `CopiarNomeAsync`) compartilhadas com o WebView. Para pastas, "Atualizar" (`mfiAtualizar`): `AtualizarPasta` relê de forma incremental (`AtualizarFilhos`), mantendo os nós existentes, removendo os que sumiram, inserindo os novos na ordem e repetindo nas subpastas expandidas; subpastas carregadas mas recolhidas voltam a `HasUnrealizedChildren`. Pasta ainda não carregada não faz nada.
  - `AlternarArvore`: zera a largura de `colArvore` (guardando `ActualWidth` em `_larguraArvore`) e oculta árvore e divisória; ao mostrar restaura, respeitando `LarguraMinimaArvore`.
- **Visualizador** (`JanelaPrincipal.Preview.cs`):
  - `wwwroot/preview-md-json-xml.html` é uma **cópia** do projeto `D:\Fontes\preview-html` (não é link).
  - Servido por `SetVirtualHostNameToFolderMapping("preview.local", ...)` em `https://preview.local/preview-md-json-xml.html` (contexto seguro para `navigator.clipboard` e `localStorage` persistente).
  - Dados do WebView2 em `%LocalAppData%\MarkdownEditor\WebView2` (variável `WEBVIEW2_USER_DATA_FOLDER`, definida antes do `EnsureCoreWebView2Async` dos dois WebView2). Runtime ausente é detectado por `CoreWebView2Environment.GetAvailableBrowserVersionString()` → oferece abrir `UrlDownloadWebView2`.
  - Para exibir um arquivo, o C# chama `renderContent(texto, nome)` via `ExecuteScriptAsync`, com os argumentos serializados por `JsonSerializer.Serialize`.
  - Enquanto a página não terminou de carregar (`NavigationCompleted`), o arquivo fica em `_arquivoPendente` e é exibido em seguida.
  - Menu de contexto: `CoreWebView2_ContextMenuRequested` acrescenta ao menu nativo (separador + as mesmas 3 opções da árvore) referentes ao `trvPastas.SelectedNode`; sem item selecionado, as opções ficam desabilitadas.
  - **Segurança** (o Markdown pode ter HTML/JS embutido, pois o HTML usa `innerHTML` sem sanitizar): `WebMessageReceived` ignora mensagens cujo `e.Source` não seja a página esperada; `NavigationStarting` só permite a própria página (`PermitirSomente`); `NewWindowRequested` é cancelado; `AbrirLinkAsync` só abre `http`/`https`/`mailto` no shell, recusa UNC, abre pastas existentes no Explorer, exibe os formatos suportados e, para qualquer outro arquivo, **nunca executa** — só `AbrirNoExplorerAsync("/select,...")`. `ConfigurarSeguranca`: `AreHostObjectsAllowed = false`, `IsStatusBarEnabled = false` e `AreDevToolsEnabled = false` fora do Debug.
  - Arrastar/soltar arquivos do Explorer é tratado pelo WinUI, não pela página (o WebView2 do WinUI não repassava o arquivo ao HTML): `ConfigurarArrastarSoltar` liga `AllowDrop` no `grdRaiz` (no `grdConteudo` não funcionava) e registra `DragOver`/`Drop` com `handledEventsToo`; o `Drop` lê `GetStorageItemsAsync` (com `GetDeferral`) e chama `AbrirArquivoArrastadoAsync` (formato suportado → `ConfirmarDescarteAsync` → seleciona na árvore → `ExibirArquivoAsync`; recusado/cancelado → `RestaurarPreviaAsync`). Vale para os dois modos (Visualizar e Editar); o `editor.html` aceita `dragover` de arquivos (`dropEffect = 'copy'`) e o Monaco tem `dropIntoEditor` desligado. Sobre a árvore não é possível soltar (o `TreeView` anula o arraste).
  - **Problema conhecido:** em testes simulados (OLE `DoDragDrop` de outro processo), arrastes alternados não chegavam ao WinUI (nenhum `DragEnter`), possivelmente pela janela própria do WebView2 (`Chrome_WidgetWin_0`). Se o usuário relatar falhas intermitentes, investigar a partir daí.
  - Colar (Ctrl+V), tema, copiar e imprimir são recursos nativos do HTML e funcionam sem código C#.
  - Leitura de arquivos via `LerArquivoAsync` (`FileShare.ReadWrite | FileShare.Delete`). Devolve também a codificação (padrão UTF-8 sem BOM; BOM detectado é preservado ao salvar).
- **Edição** (`JanelaPrincipal.Editor.cs` + `wwwroot/editor.html`):
  - Editor **Monaco 0.52.2** (última versão com build AMD suportado, sem bundler) em `wwwroot/monaco/vs`, reduzido a Markdown, XML e JSON (`VERSAO.txt`, `LICENSE`). Página própria `editor.html` (não vem do `preview-html`), servida em `https://preview.local/editor.html` pelo `wvwEditor` (mesmas configurações de segurança + `AreBrowserAcceleratorKeysEnabled = false`, para F5 não recarregar a página).
  - Ponte C# → página por `ExecuteScriptAsync` (`ExecutarNoEditorAsync`, que espera `_editorPronto`): `carregar(texto, linguagem)` (modelo novo: zera o desfazer e marca o ponto salvo), `recarregar(texto)` (mantém cursor/rolagem), `obterConteudo()` → `{ texto, versao }`, `marcarSalvo(versao)`, `desfazerAlteracoes(texto)` (uma edição só, Ctrl+Z recupera), `definirLinguagem`, `definirTema`, `focar`. As funções devolvem `{ modificado, vazio }` (`EstadoEditor`), aplicado em `_editorModificado`/`_editorVazio`.
  - Página → C# por `postMessage` (`Editor_WebMessageReceived`, só de `PaginaEditor`): `pronto`, `alterado:` + estado (só edições do usuário; marca `_previaDesatualizada`), `salvar` (Ctrl+S dentro do Monaco), `navegar:voltar`/`navegar:avancar` (Alt+setas, teclas e botões laterais do mouse).
  - "Modificado" = `getAlternativeVersionId() !== pontoSalvo`. Salvar lê texto + versão e marca **aquela** versão como salva (o que for digitado durante a gravação continua como alteração).
  - Linguagem por extensão (`LinguagemEditor`): `markdown` (padrão e texto colado), `json`, `xml`, `plaintext` (.txt). Tema `vs`/`vs-dark`.
  - "Abas" = `sgmModo`; `AlternarModoAsync` alterna a visibilidade de `wvwPreview`/`wvwEditor` e mostra Salvar/Desfazer só no modo Editar.
  - Todo conteúdo exibido também é carregado no editor por `CarregarNoEditorAsync(texto, caminho?, codificação?)` (arquivo, texto colado, histórico, arquivo solto, "Novo"). Guarda `_textoOriginal` (último conteúdo conhecido em disco ou o texto colado) e `_codificacaoAtual`.
  - Alterações não salvas: `_previaDesatualizada` faz a prévia re-renderizar o texto do editor ao voltar para Visualizar (`AtualizarPreviaAsync`, preservando rolagem via `RenderizarPreservandoRolagemAsync`). O título ganha `*` com `_editorModificado`.
  - Gravação atômica: `GravarArquivoAsync` → `GravarComSubstituicaoAsync` grava em `~nome.ext.<guid>.tmp` na mesma pasta e troca com `File.Replace` (ou `File.Move` se o destino não existe); se falhar, grava direto no arquivo como fallback.
  - `abbSalvar` (e Ctrl+S no modo Editar) habilita com `_editorModificado` ou quando não há arquivo e existe texto (texto colado). `SalvarAsync` grava na mesma codificação; sem arquivo vai para `SalvarComoAsync` (`Microsoft.Windows.Storage.Pickers.FileSavePicker(AppWindow.Id)`, `SuggestedFolder` = `PastaInicialSalvar`), que define o arquivo atual, troca `_entradaAtual`, recarrega a pasta na árvore e seleciona o arquivo (`MostrarNaArvore`).
  - `abbDesfazer` (habilitado com `_editorModificado`): `DesfazerAlteracoesAsync` volta o texto para `_textoOriginal` sem limpar o desfazer.
  - `ConfirmarDescarteAsync` (Salvar/Não salvar/Cancelar; "Não salvar" volta o editor para `_textoOriginal`) é chamado na seleção da árvore, `NavegarHistoricoAsync`, `AbrirLinkAsync`, fechamento (`AppWindow.Closing` cancela e chama `Close()` depois de confirmar) e nos fluxos que o HTML já exibiu sozinho (colar, soltar, "Novo") — nestes, se cancelado, `RestaurarPreviaAsync` volta a prévia ao texto do editor.
- **Atualização automática do arquivo exibido** (`JanelaPrincipal.Monitor.cs`):
  - Toda troca do arquivo atual passa por `DefinirArquivoAtual(caminho?)` (atualiza `_arquivoAtual`, título e o monitor). Texto colado ou "Novo" → `null` (sem monitor).
  - `MonitorarArquivo` cria um `FileSystemWatcher` só para o arquivo exibido (pasta + `Filter` = nome): notificações do Windows, sem polling e sem abrir o arquivo. Os eventos chegam no pool de threads e voltam para a interface por `DispatcherQueue.TryEnqueue`.
  - Os eventos apenas reiniciam o `_temporizadorRecarga` (`DispatcherQueueTimer`, debounce de `IntervaloRecargaMs`). No `Tick` o estado real é conferido com `File.Exists` — isso cobre o salvamento atômico dos editores.
  - Existe → `RecarregarArquivoAsync`: se o conteúdo for igual a `_textoOriginal` não faz nada (cobre o próprio salvamento); senão recarrega editor (mantendo cursor/rolagem) e prévia preservando `stage.scrollTop`, sem histórico e sem mexer na árvore. Com alterações pendentes, pergunta antes se descarta. `IOException` reagenda silenciosamente até `MaximoTentativasRecarga`.
  - Não existe → `TratarArquivoExcluidoAsync`: desliga o monitor, remove o(s) nó(s) da árvore (`LocalizarNosCarregados`, sem expandir), avisa e fecha a visualização (`newBtn.click()` no HTML e limpa o arquivo atual). Com alterações pendentes, mantém o texto como não salvo (sem arquivo; Salvar abre o "Salvar como").
  - O clique no botão "Novo" do HTML é avisado pelo `ScriptMonitorarEventos` com a mensagem `novo`.
  - `ScriptMonitorarEventos` é injetado no preview via `AddScriptToExecuteOnDocumentCreatedAsync` (sem alterar o HTML) e avisa o C# por `postMessage`: `arquivoSolto` (só o botão "Escolher arquivo"; o arrastar é do WinUI), `textoColado:` + texto, `abrirLink:` + destino, `navegar:voltar` / `navegar:avancar`, `tema:light` / `tema:dark`, `novo`.
- **Tema** (`JanelaPrincipal.Tema.cs`):
  - Acompanha o tema do HTML. O script calcula o tema efetivo (`data-theme` em `<html>` ou, se ausente, `prefers-color-scheme`) e envia `tema:` no `DOMContentLoaded`, a cada mudança do atributo e quando o tema do Windows muda.
  - Na abertura, usa o tema do Windows (`Application.Current.RequestedTheme`; o `App.xaml` não fixa tema).
  - `AplicarTema(bool escuro)`: `grdRaiz.RequestedTheme` (Mica, `TitleBar`, árvore, `CommandBar`, menus e diálogos seguem), `AppWindow.TitleBar.PreferredTheme` (botões de legenda), `DefaultBackgroundColor` dos dois WebView2 (#1E1E1E/#FFFFFF, para evitar "flash") e `definirTema` no Monaco.
- **Histórico Voltar/Avançar** (`JanelaPrincipal.Historico.cs`):
  - `record EntradaHistorico(string? Caminho, string? Texto)`: um arquivo ou um texto colado (exibido como "texto colado").
  - Pilhas `_historicoVoltar` / `_historicoAvancar` (`LinkedList`, limitadas a `LimiteHistorico = 10`) e `_entradaAtual`. `RegistrarNoHistorico` ignora a entrada igual à atual (`MesmaEntrada`) e limpa o "avançar".
  - `NavegarHistoricoAsync` exibe a entrada (`ExibirEntradaAsync`: seleciona o arquivo na árvore e chama `ExibirArquivoAsync(..., registrarHistorico: false)`, ou re-renderiza o texto). Se o arquivo não puder ser exibido, a entrada é descartada.
  - Botões ficam desabilitados quando a pilha está vazia; o tooltip mostra o nome do destino (`AtualizarBotoesNavegacao`).
  - Atalhos: `KeyboardAccelerator` Alt+← / Alt+→ e `GoBack`/`GoForward` nos botões (fora dos WebView2); os botões laterais do mouse chegam por esse mesmo caminho, porque o Windows os converte no comando Voltar/Avançar (`WM_APPCOMMAND` → `GoBack`/`GoForward`) — **não** tratar `XButton1`/`XButton2` no `PointerPressed`, senão a navegação acontece duas vezes (no down pelo `PointerPressed` e no up pelo comando do Windows); dentro dos WebView2, pelos scripts das páginas.

## Geração do Instalador

Gerado com **Inno Setup** (`iscc` no PATH). Arquivos: `MarkdownEditor\Instalador\Instalador.iss` e `Release.cmd` (raiz), baseados no projeto `D:\Growdev\Refere\AutomacaoBrowser`.

- `Release.cmd`: `dotnet publish MarkdownEditor\MarkdownEditor.csproj -c Release -r win-x64 --self-contained false -o MarkdownEditor\bin\Publicar` → apaga o `MarkdownEditor-*.exe` anterior → `iscc MarkdownEditor\Instalador\Instalador.iss`. O `.exe` é gerado em `MarkdownEditor\Instalador\` (ignorado no git).
- .NET **framework-dependent** (a máquina precisa do .NET 10 Runtime) e Windows App SDK **self-contained** (não precisa do Windows App Runtime). O instalador copia tudo de `MarkdownEditor\bin\Publicar\` (inclui `wwwroot\` com o Monaco e `Assets\`) para `{commonpf}\MarkdownEditor`.
- `AppId=Markdown Editor` fixo (não alterar, para não quebrar upgrades e desinstalação). `[Code]` → `InitializeSetup` verifica o .NET 10 Runtime (`{commonpf64}\dotnet\shared\Microsoft.NETCore.App\10.*`) e o WebView2 Runtime (valor `pv` em `EdgeUpdate\Clients\{F3017226-...}`, HKLM WOW6432Node ou HKCU); se faltar, avisa e oferece abrir a página de download, sem interromper a instalação.
- Registro (root `HKA`, removido na desinstalação):
  - ProgID `MarkdownEditor.Arquivo` (`shell\open\command` = `"{app}\MarkdownEditor.exe" "%1"`) e `Applications\MarkdownEditor.exe\SupportedTypes`.
  - Sempre: `OpenWithProgids` de `.md`, `.markdown`, `.json`, `.xml` e `.txt` → opção no "Abrir com".
  - Tarefa opcional `associarmd` (desmarcada): grava `MarkdownEditor.Arquivo` como valor padrão de `.md` e `.markdown`.
  - **Comportamento esperado:** no Windows 10/11 um instalador não consegue definir o app padrão — a escolha do usuário fica em `UserChoice` (protegida por hash) e prevalece. Por isso, no primeiro duplo clique após a instalação, o Windows pergunta qual aplicativo usar, mesmo com `associarmd` marcada; o usuário escolhe o Markdown Editor e marca "Sempre". Isso é normal e foi decidido manter assim (não usar ferramentas que contornam o hash do `UserChoice`).
- Antes de gerar, atualizar a versão em:
  1. `Instalador.iss`: `AppVersion` e `OutputBaseFilename` (`MarkdownEditor-X.Y.Z`).
  2. `MarkdownEditor.csproj`: `AssemblyVersion`, `FileVersion` e `InformationalVersion`.
  3. `app.manifest`: `assemblyIdentity version` (`X.Y.Z.0`).

## Convenções

- Textos de interface, nomes de variáveis, métodos e controles em português (pt-BR).
- Prefixos de controles: `tlb` (TitleBar), `cbr` (CommandBar), `abb` (AppBarButton), `abs` (AppBarSeparator), `sgm` (Segmented), `grd` (Grid), `col` (ColumnDefinition), `gsp` (GridSplitter), `trv` (TreeView), `wvw` (WebView2), `mfo` (MenuFlyout), `mfi` (MenuFlyoutItem), `mfs` (MenuFlyoutSeparator). A janela é `JanelaPrincipal`.
- Cores e estilos por recursos de tema do WinUI (`ThemeResource`); evitar cores fixas (exceção: fundo dos WebView2).
- Não adicionar comentários XML `<summary>` em métodos novos.
- P/Invoke só se não houver API do WinUI/Windows App SDK/WinRT que funcione; vai em `NativeMethods.cs`, preferindo `LibraryImport`.
- Analisadores: `AnalysisLevel` = `latest-recommended`; o build deve ficar com 0 avisos.
- Não alterar o HTML do visualizador (`wwwroot/preview-md-json-xml.html`) para integrar com o C#; preferir chamar as funções já existentes. Se o HTML precisar mudar, avaliar se a mudança deve ir também para o projeto `preview-html` original. O `editor.html` é deste projeto e pode ser alterado.
- Monaco: para atualizar, trocar `wwwroot/monaco/vs` pelo `min/vs` do pacote npm `monaco-editor` (manter só `base`, `editor`, `loader.js`, `basic-languages/markdown`, `basic-languages/xml` e `language/json`) e atualizar `VERSAO.txt` e a constante `VersaoMonaco` (`JanelaPrincipal.Sobre.cs`). Versões 0.53+ abandonaram o build AMD usado pelo `editor.html`.
- Não há testes automatizados; a verificação é feita executando o programa.
